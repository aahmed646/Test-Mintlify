The Users API lets you programmatically manage every user in your Google workspace. Use these endpoints to automate user provisioning, update roles, and remove access — all from your own applications or scripts.

## GET /users

Retrieve a paginated list of all users in your workspace. Use the `cursor` parameter to page through large result sets and `role` to filter by permission level.

<ParamField query="limit" type="integer" default={20}>
  The maximum number of users to return per page. Accepted range: 1–100.
</ParamField>

<ParamField query="cursor" type="string">
  An opaque pagination cursor returned by the previous response. Pass this value to fetch the next page of results.
</ParamField>

<ParamField query="role" type="string">
  Filter results to users with a specific role. Accepted values: `viewer`, `editor`, `admin`.
</ParamField>

**Response fields**

<ResponseField name="data" type="array">
  An array of user objects matching the query.

  <Expandable title="User object">
    <ResponseField name="id" type="string">Unique identifier for the user.</ResponseField>
    <ResponseField name="name" type="string">Full display name of the user.</ResponseField>
    <ResponseField name="email" type="string">Email address associated with the user account.</ResponseField>
    <ResponseField name="role" type="string">Permission level: `viewer`, `editor`, or `admin`.</ResponseField>
    <ResponseField name="created_at" type="string">ISO 8601 timestamp of when the user was created.</ResponseField>
    <ResponseField name="updated_at" type="string">ISO 8601 timestamp of the most recent update.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="next_cursor" type="string">
  Pagination cursor to pass as `cursor` in your next request. `null` when you have reached the last page.
</ResponseField>

<ResponseField name="total" type="integer">
  Total number of users matching the query, across all pages.
</ResponseField>

```bash
curl -X GET "https://api.google.com/v1/users?limit=20&role=editor" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## POST /users

Create a new user in your workspace. The user receives an invitation email at the address you provide.

<ParamField body="name" type="string" required>
  Full display name for the new user.
</ParamField>

<ParamField body="email" type="string" required>
  Email address for the new user. Must be unique across your workspace.
</ParamField>

<ParamField body="role" type="string" required>
  Permission level to assign. Accepted values: `viewer`, `editor`, `admin`.
</ParamField>

**Response fields**

<ResponseField name="id" type="string">Unique identifier assigned to the newly created user.</ResponseField>
<ResponseField name="name" type="string">Full display name of the user.</ResponseField>
<ResponseField name="email" type="string">Email address of the user.</ResponseField>
<ResponseField name="role" type="string">Permission level assigned to the user.</ResponseField>
<ResponseField name="created_at" type="string">ISO 8601 timestamp of when the user was created.</ResponseField>
<ResponseField name="updated_at" type="string">ISO 8601 timestamp of the most recent update.</ResponseField>

```bash
curl -X POST "https://api.google.com/v1/users" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Alan Turing",
    "email": "alan@example.com",
    "role": "viewer"
  }'
```

```json
{
  "id": "usr_01hx9k2p5s",
  "name": "Alan Turing",
  "email": "alan@example.com",
  "role": "viewer",
  "created_at": "2025-01-10T16:05:00Z",
  "updated_at": "2025-01-10T16:05:00Z"
}
```

## PATCH /users/\{id\}

Update one or more fields on an existing user. Send only the fields you want to change — all other fields remain unchanged.

<ParamField path="id" type="string" required>
  The unique identifier of the user to update.
</ParamField>

<ParamField body="name" type="string">
  New display name for the user.
</ParamField>

<ParamField body="email" type="string">
  New email address for the user. Must be unique across your workspace.
</ParamField>

<ParamField body="role" type="string">
  New permission level. Accepted values: `viewer`, `editor`, `admin`.
</ParamField>

**Response fields**

<ResponseField name="id" type="string">Unique identifier of the updated user.</ResponseField>
<ResponseField name="name" type="string">Current display name of the user.</ResponseField>
<ResponseField name="email" type="string">Current email address of the user.</ResponseField>
<ResponseField name="role" type="string">Current permission level of the user.</ResponseField>
<ResponseField name="created_at" type="string">ISO 8601 timestamp of when the user was created.</ResponseField>
<ResponseField name="updated_at" type="string">ISO 8601 timestamp reflecting this update.</ResponseField>

<Note>
  You cannot demote the last `admin` user in a workspace. The API returns a `409 Conflict` error if you attempt this.
</Note>

```bash
curl -X PATCH "https://api.google.com/v1/users/usr_01hx9k2p5s" \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "role": "editor"
  }'
```

```json
{
  "id": "usr_01hx9k2p5s",
  "name": "Alan Turing",
  "email": "alan@example.com",
  "role": "editor",
  "created_at": "2025-01-10T16:05:00Z",
  "updated_at": "2025-01-10T17:30:00Z"
}
```

## DELETE /users/\{id\}

Permanently remove a user from your workspace. This action is irreversible and immediately revokes the user's access.

<ParamField path="id" type="string" required>
  The unique identifier of the user to delete.
</ParamField>

A successful deletion returns `204 No Content` with an empty response body.

<Warning>
  Deleting a user cannot be undone. Any resources owned by this user remain in the workspace but are reassigned to the requesting admin. Consider updating the user's role to `viewer` first if you want to preserve audit continuity.
</Warning>

```bash
curl -X DELETE "https://api.google.com/v1/users/usr_01hx9k2p5s" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```
HTTP/1.1 204 No Content
```
