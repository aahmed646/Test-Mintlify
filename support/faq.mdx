<Accordion title="How do I reset my API key?">
You can regenerate your API key at any time from the Google Developer Console. Keep in mind that resetting your key immediately invalidates the old one — any services using it will stop authenticating until you update them.

1. Go to [console.google.com](https://console.google.com) and sign in.
2. Navigate to **Settings → API Keys**.
3. Locate the key you want to reset and click **Regenerate**.
4. Copy the new key and update it everywhere it's used — environment variables, CI/CD secrets, and any third-party integrations.

<Warning>
Regenerating a key is irreversible. Your old key stops working immediately, so make sure you update all dependent services before or right after regenerating.
</Warning>
</Accordion>

<Accordion title="What are the rate limits?">
Rate limits depend on your plan and the specific API you're calling. By default, limits are enforced per API key on a rolling 60-second window.

| Plan       | Requests / minute | Requests / day |
|------------|-------------------|----------------|
| Free       | 60                | 1,000          |
| Starter    | 300               | 10,000         |
| Pro        | 1,000             | 100,000        |
| Enterprise | Custom            | Custom         |

When you exceed a limit, the API responds with `HTTP 429 Too Many Requests`. The response includes a `Retry-After` header that tells you how many seconds to wait before retrying.

```http
HTTP/1.1 429 Too Many Requests
Retry-After: 30
X-RateLimit-Limit: 300
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1714000830
```

<Tip>
Use exponential backoff in your retry logic to avoid thundering-herd problems. See the [Troubleshooting guide](/support/troubleshooting) for a code example.
</Tip>
</Accordion>

<Accordion title="How do I add team members to my account?">
You can invite team members from the **Members** section of your account settings. Each member gets their own login and can be assigned a role that controls what they can see and do.

1. Open **Settings → Team Members**.
2. Click **Invite Member**.
3. Enter their email address and choose a role:
   - **Owner** — full access including billing and key management
   - **Admin** — full access except billing
   - **Developer** — API access and logs, no billing or team management
   - **Viewer** — read-only access to dashboards and logs
4. Click **Send Invite**. The invitee receives an email with a link to accept.

<Note>
Invitations expire after 7 days. If a team member misses the email, resend the invite from **Settings → Team Members → Pending Invites**.
</Note>
</Accordion>

<Accordion title="Can I use Google's API in a mobile app?">
Yes — you can call Google APIs from iOS, Android, and cross-platform mobile frameworks. However, you should never embed your secret API key directly in a mobile app binary, since it can be extracted by users.

The recommended pattern is to route API calls through your own backend server:

```
Mobile App  →  Your Backend Server  →  Google API
```

Your backend holds the secret key securely and proxies requests on behalf of the app. If you need the app to authenticate end users directly, use OAuth 2.0 so each user gets their own access token with limited scope.

<Warning>
Hard-coding a secret API key in a mobile app is a serious security risk. Rotate any key you believe has been exposed immediately from **Settings → API Keys**.
</Warning>
</Accordion>

<Accordion title="How do I cancel my subscription?">
You can cancel your paid plan at any time from the Billing section of your account. Your access continues until the end of the current billing period — you won't be charged again after that.

1. Go to **Settings → Billing**.
2. Click **Manage Subscription**.
3. Select **Cancel Plan** and follow the confirmation prompts.

After cancellation your account automatically downgrades to the Free plan. Your data, API keys, and configuration are preserved — only usage limits change.

<Note>
If you cancel within the first 30 days of a new paid plan, contact [support@google.com](mailto:support@google.com) to request a refund under our money-back guarantee.
</Note>
</Accordion>

<Accordion title="What happens if my webhook endpoint goes down?">
Google retries failed webhook deliveries automatically using an exponential backoff schedule. If your endpoint returns a non-2xx response or times out, we'll retry up to **5 times** over the next **24 hours**.

| Attempt | Delay after previous attempt |
|---------|------------------------------|
| 1st retry | 5 minutes |
| 2nd retry | 30 minutes |
| 3rd retry | 2 hours |
| 4th retry | 6 hours |
| 5th retry | 16 hours |

After all retries are exhausted, the event is marked as **Failed** in the **Webhooks → Delivery Logs** section of your dashboard, where you can inspect the payload and manually replay it once your endpoint is back online.

<Tip>
Acknowledge webhook events quickly by responding with `HTTP 200` as soon as you receive them, then process the payload asynchronously. This prevents timeouts from triggering unnecessary retries.
</Tip>
</Accordion>

<Accordion title="How do I upgrade my plan?">
You can upgrade your plan instantly from your billing settings — the change takes effect immediately and you're billed a prorated amount for the remainder of your current cycle.

1. Go to **Settings → Billing**.
2. Click **Upgrade Plan**.
3. Select the plan that fits your needs and click **Confirm Upgrade**.
4. Your new rate limits and features are available right away.

If you're on the Enterprise plan or need a custom quote, contact our sales team at [sales@google.com](mailto:sales@google.com).
</Accordion>

<Accordion title="Where can I find API usage logs?">
Detailed request logs are available in the **Logs** section of the Google Developer Console. You can filter, search, and export logs to diagnose issues or audit usage.

- **Dashboard → Logs → API Requests** — per-request log with status codes, latency, and request/response bodies (up to 10 KB).
- **Dashboard → Logs → Errors** — a filtered view of 4xx and 5xx responses.
- **Dashboard → Analytics** — aggregate usage charts broken down by endpoint, key, and time period.

Logs are retained for **30 days** on the Free and Starter plans and **90 days** on Pro and Enterprise.

<Tip>
You can stream logs in real time to your own observability stack using the [Log Export API](https://developers.google.com/logs/export) or by configuring a log-drain webhook under **Settings → Integrations**.
</Tip>
</Accordion>

<Accordion title="Is there a sandbox or test environment?">
Yes. Every Google account includes a free sandbox environment that mirrors production features but uses separate data and never triggers real-world side effects (such as sending emails or processing payments).

To use the sandbox:

1. Prefix your API key with `test_` — sandbox keys are issued from **Settings → API Keys → Create Key → Sandbox**.
2. Point your requests to the same base URL; the sandbox is activated by the key prefix, not a different host.
3. All sandbox data is isolated from production — you can create, update, and delete resources freely without affecting live data.

```bash
# Sandbox request — note the test_ key prefix
curl -H "Authorization: Bearer test_sk_abc123" \
  https://api.google.com/v1/resources
```

<Note>
Sandbox rate limits match your plan's production limits, so it's safe to use for load testing as well as functional testing.
</Note>
</Accordion>

<Accordion title="How do I report a bug or request a feature?">
We welcome both bug reports and feature requests from customers.

- **Bug reports** — open a ticket at [support.google.com](https://support.google.com) or email [support@google.com](mailto:support@google.com). Include your account ID, the request ID from the response headers (`X-Request-ID`), reproduction steps, and the exact error message.
- **Feature requests** — post to our [Community Forum](https://community.google.com) where you can also upvote ideas from other customers. Our product team reviews the forum weekly.
- **Security vulnerabilities** — do not post publicly. Email [security@google.com](mailto:security@google.com) with a detailed description. We follow responsible disclosure and aim to respond within 24 hours.

<Tip>
When filing a bug, attach the `X-Request-ID` header value from the failing response. This lets our support team pull the exact server-side trace instantly, cutting resolution time significantly.
</Tip>
</Accordion>
